================================================================
  Dola Pool 桌面版 · 快速开始
================================================================

一、怎么打开
----------------------------------------------------------------
Windows ：双击  start-windows.bat
macOS   ：双击  start-macos.command
          （若提示"无法打开，因为来自身份不明的开发者"，
            右键 → 打开 → 再点"打开"即可）
Linux   ：终端执行  ./start-linux.sh

首次启动会自动创建运行环境并安装依赖，大约 1-3 分钟；
之后每次启动只需几秒。

前提：电脑上要有 Python 3.10 或更高版本
      下载：https://www.python.org/downloads/
      Windows 安装时务必勾选 "Add Python to PATH"

程序默认是【演示模式】：不联网、不需要账号，任务会在 6 秒左右
生成一段内置示例视频，用来先把整个流程跑通、熟悉界面。


二、要生成真实视频（生产模式）
----------------------------------------------------------------
1. 打开界面 → 左侧【设置】→ 找到「桌面应用」卡片
2. 点【切换到生产模式】→ 窗口会自动重启（几秒钟）
3. 左侧【账号池】→【批量导入】→ 粘贴你的 Dola 账号 Cookie
   （每行一个，或拖入 .txt / .csv / .json 文件）

   Cookie 从哪来：浏览器 F12 → Network（网络）→ 随便点一个 dola.com
   的请求 → Request Headers 里的 "Cookie:" 后面那一整行
   （形如 sessionid=xxxxx; sid_guard=yyyyy; ... 是一段带分号的文本，
    不是 JSON）。
4. 左侧【生成】→ 填提示词 → 【提交任务】

注意：生产模式会真实调用 Dola 生成，需要账号自身有可用额度；
      生成逻辑与原始仓库完全一致（含代理轮换与去水印），
      我没有做任何改动。账号与风控风险请自行判断。


三、生成好的视频在哪里
----------------------------------------------------------------
· 界面【任务队列】里点【▶ 播放】可以直接看，弹窗里有
  【📂 打开所在文件夹】和【⬇ 下载】
· 文件保存在（各平台不同）：
    Windows  %APPDATA%\DolaPool\output
    macOS    ~/Library/Application Support/DolaPool/output
    Linux    ~/.local/share/dola-pool/output
· 界面【设置 → 桌面应用】里也有【📂 成片目录】按钮，一键定位


四、看看某个账号在 Dola 里长什么样（🌐 网页）
----------------------------------------------------------------
账号池里每一行右边都有个【🌐 网页】按钮，点它就开一个新窗口，
里面是**这个账号登录状态下**的 Dola 页面 —— 不用自己去浏览器登录，
也不受影响你电脑上其它浏览器的登录状态。

  桌面版：弹出原生窗口（关掉主窗口时会一起关掉）
  Web 版：新开一个浏览器标签页

窗口默认直接进 Dola 的主界面（/chat/）。

它是怎么做到带登录态的（两条路，看窗口标题栏就知道走的是哪条）：
  · 真站（标题栏带「· dola.com」）—— 桌面版默认走这条：
    启动时把该账号的 Cookie 直接写进**浏览器内核自己的 Cookie 存储**
    （Windows 上是 Edge WebView2），然后打开 https://www.dola.com/chat/。
    页面就是官网本身、地址就是 dola.com，登录态已经是这个账号。
    之所以能做到：内核提供了 Cookie 管理接口（WebView2 的 CookieManager），
    连 HttpOnly 的 Cookie 也能写进去，而普通网页脚本是写不了的。

    注意：浏览器内核**不读** DOLA_PROXY / HTTPS_PROXY 这两个环境变量，
    它只认系统代理设置。所以如果这台机器上网必须走代理，而代理只写在环境变量里，
    内核其实是在直连 dola.com —— 会被挡住，窗口就停在空白页（右键菜单还在）。
    从 v2.0.10 起，启动器会把内核的请求也挂到同一个代理上（见下面「代理」一节），
    并且**打开真站后会自己检查有没有渲染出来**，没渲染出来就换成一张诊断页，
    把卡在哪一步直接写给你看，不再干白着。

  · 本机代理页（标题栏带「· 本机代理页」）—— 上面那条走不通时的兜底：
    在你本机跑一个只服务自己的小代理，窗口访问的是
    http://127.0.0.1:端口/dola-web/账号ID/…，由后端把这个账号的 Cookie
    加到请求里再转发给 Dola。（非 Windows、或内核接口没就绪时会退到这条。）

注意：浏览器内核的 Cookie 是所有窗口共用的，所以**同一时间只有一个账号是「活的」**——
打开另一个账号时，上一个账号的窗口会被收进后台（挂起），而不是关掉；
它上面的登录态会被新账号顶掉，切回去时会自动重新写入 Cookie 并刷新（1-3 秒）。
真站窗口里如果显示成未登录，说明这个账号的 Cookie 已经失效，
去账号池【✓ 验活】重新导一次即可。

多账号快速切换（v2.0.12）：账号池表格里的「窗口」一列 + 页面下方的「窗口会话」卡片，
每个账号有三种状态：
  ▶ 运行中（前台显示中） —— 窗口正开着，就是它
  ❚❚ 已挂起（后台挂起）  —— 窗口建好了但不显示，登录态和真站页面先在后台准备好；
                            点【切换过去】只是把窗口显示出来，不用等加载
  ⚠ 需重连             —— 挂起中，但登录态已经被别的账号顶掉；
                            点【切换过去】会自动重连（重新写入 Cookie + 刷新）
  ⛔ 已关闭             —— 没有窗口
两个按钮的区别：
  【前台打开】 —— 直接弹窗口（等它加载）
  【后台挂起】 —— **不弹窗**！先把这个账号在后台挂起来，你手头的事不被打断，
                 等要切换时点【切换过去】，窗口秒开

「本机代理页」模式窗口底部那条细提示是：
  🔗 本地代理 · 账号 #2 名字 ｜ 🌐 用系统浏览器打开 ｜ ↻ 重载 ｜ ⚠ n ｜ ✕ 隐藏

  · 🌐 用系统浏览器打开 —— 用 Chrome/Edge 打开**同一个带登录态的页面**
                              （不是不带登录态的官网）。桌面窗口万一渲染不出来，
                              点这个就能换个浏览器对照。
  · ↻ 重载         —— 重新加载当前页
  · ⚠ n            —— 有 n 个出错的请求 / 脚本错误，点一下展开看具体是什么
  · ✕ 隐藏         —— 把这条收掉


五、导出 / 修改账号（v2.0.12）
----------------------------------------------------------------
账号池页面上排按钮：
  ⤓ 导出 CK  —— 把账号池里的 Cookie 导出成文件（**完整 Cookie，不打码**）：
      · JSON：名字 / 备注 / 每日上限都保留，导回来名字不丢（推荐用来备份）
      · TXT ：每行一个完整 Cookie（最通用，能直接粘到别处，也能再导回本站）
      · CSV ：Excel 能直接打开（name,cookie,note 三列）
    文件是浏览器下载的文件（dola-ck-N-时间.json/txt/csv），存在你的下载文件夹。
    提醒：拿到 Cookie 等于拿到账号，导出文件别发给别人。

  每一行右边的【✎ 编辑】可以改：
      · ID 名称        —— 自己看得懂就行，例如「主号 A」
      · 备注           —— 例如「这个号只跑竖屏」
      · 每日上限       —— 这个号单独的上限（0 = 用全局设置里的每日每号限额）
      · 今日用量       —— 手动手动设置「今天已经用了多少次」：
                          填 0 = 今天先别用这个号；留空 = 回到按任务真实统计
                          （手动值只对当天有效，第二天自动失效）
      · 状态           —— active / ready（可用）、paused（暂停，不参与自动选号）、
                          invalid（失效，不参与自动选号）


★ 如果窗口里是白屏 / 页面残缺，按这个顺序排查：
  1. 先看窗口标题栏，它一定写着走的是哪条：
       · dola.com            → 真站，而且启动器已确认页面渲染出来了
       · 真站打不开（窗口里有说明） → 换成了诊断页，窗口里会写清楚卡在哪一步
       · 本机代理页           → 走的本机代理（服务端带着 Cookie 去取 Dola）
  2. 标题栏写着「真站打不开」时，窗口里那张诊断页就是答案，看这几行：
       地址：about:blank            → 内核根本没把 dola.com 取回来（网络 / 代理问题）
       地址：chrome-error://…       → 导航被中断（同样是网络层）
       地址：https://www.dola.com/… 但正文几乎是空的 → 页面到了、脚本没跑起来
     页面上有三个按钮：◀ 改看本机代理页、↻ 重新打开真站、🌐 用系统浏览器打开。
  3. 想先干活不等修：点「◀ 改看本机代理页」，这条路由后端取页面，一般都能显示。
  4. 本机代理页底部那条细提示是：
       🔗 本地代理 · 账号 #2 名字 ｜ 🌐 用系统浏览器打开 ｜ ↻ 重载 ｜ ⚠ n ｜ ✕ 隐藏
       · 🌐 用系统浏览器打开 —— 用 Chrome/Edge 打开**同一个带登录态的页面**
       · ↻ 重载         —— 重新加载当前页
       · ⚠ n            —— n 个出错的请求 / 脚本错误，点一下展开看具体是什么
       · ✕ 隐藏         —— 把这条收掉
  5. 还是不行就把这两样发我：窗口里诊断页上的那几行数字 + 黑窗口里
     「[desktop] v2.0.16 自检」那几行。我按里面的数字继续修。

★ 代理：让窗口和「验活」走同一条路
  账号池里的【✓ 验活】是后端（Python）去连 dola.com，它会读 DOLA_PROXY /
  HTTPS_PROXY 环境变量；而浏览器内核不读这两个变量（只认系统代理），
  于是可能出现「验活说 dola.com 可达，窗口却白屏」——
  因为一个走了代理、一个在直连。
  v2.0.10 起，启动器在建窗口之前会把内核也挂到**同一个代理**上，优先级是：
    1) config.json 里的 proxy 字段（或启动参数 --proxy 地址）
    2) 环境变量 DOLA_PROXY
    3) 环境变量 HTTPS_PROXY / HTTP_PROXY
  代理带账号密码时会自动在本机起一个只服务自己的小中转，由它带着账号密码去连
  上游（因为 Chromium 的 --proxy-server 不支持把密码写在地址里，会报
  ERR_NO_SUPPORTED_PROXIES）。本机地址（127.0.0.1）始终直连，不走代理。
  想手动指定，两种办法都行：
    · 在程序目录的 config.json 里加一行：
        "proxy": "http://用户名:密码@主机:6666"
    · 或者启动时加参数：DolaPool.exe --proxy http://用户名:密码@主机:6666
  想让窗口完全直连（比如系统代理才是对的）：加 --no-proxy 启动，
  或把 config.json 里的 proxy 删掉。
  启动后黑窗口会有一行写明走的是哪条，例如：
    [desktop] 浏览器内核网络：经本机中转 http://127.0.0.1:52341 → 主机:6666（来自 HTTPS_PROXY；本机地址直连）

★ 如果窗口里是「一整页代码 / 乱码」（看到的是脚本源码，不是页面）：
  那是 v2.0.5 之前的打包 bug —— 注入页面的脚本忘了在外面套 <script> 标签，
  浏览器就把这段代码当普通文字铺满窗口了（不是 Dola 的问题，也不是你操作的问题）。
  装 v2.0.5 及以后即可。
  怎么确认装的是哪一版：左边侧栏最下面显示  v2.0.16 · 桌面版  就是新版；
  如果显示 v2.0.0，说明打开的还是旧包 —— 请把新包重新解压
  （旧的解压目录先删掉，别和新包混在一起）。

★ 如果窗口里能显示 Dola，但**点一下就卡死 / 未响应**（v2.0.10 及更早）：

  症状：黑窗口里刷满 Empty. Empty. Empty. …，最后一行是
        maximum recursion depth exceeded，程序以错误码 -805306369 退出
        （Windows 的「栈溢出」，不是崩溃在浏览器里，而是 Python 这边被递归走爆）。
  原因：账号窗口里挂了 JS 桥 —— 我把窗口对象暴露给了页面。而 pywebview 在
        每次页面加载完成时都会把 js_api 对象整个遍历一遍（对每个属性
        getattr、再递归进子对象）。真站脚本一有动作就触发，遍历一路走进
        .NET 控件（win.native.webview.…），把栈走爆 → 整个进程死掉。
        （我用 pywebview 自己的代码复现过：暴露对象时它对我放的探针访问了
         5075 次；不暴露时 0 次。）
  v2.0.11 起：账号窗口不传 js_api、也不注入任何脚本，页面里不留
        window.pywebview；诊断页的按钮改成普通链接 + 本机 HTTP 端点
        （/api/desktop/open-external）—— 真站上我们什么都不碰。

★ 如果窗口里是一片空白（白屏）：

  v2.0.10 及以后：窗口里不会再干白着 —— 启动器打开真站后会自检，
  渲染不出来就换成一张诊断页，写明卡在哪一步，并给你三个按钮
  （改看本机代理页 / 重新打开真站 / 用系统浏览器打开）。
  先把诊断页上的那几行发我即可。

  如果是 v2.0.8 及更早，而且黑窗口里刷过这么一行：
     System.InvalidOperationException: CoreWebView2 can only be accessed
     from the UI thread
  那是 v2.0.8 的 bug：浏览器内核（WebView2）只能在界面线程里访问，
  而这个版本是在后台线程里读的，线程一挂窗口就停在空白页。
  v2.0.9 已修（探测内核和写 Cookie 全放回界面线程），装 v2.0.9 及以后即可。
  v2.0.9 起，注入 Cookie 的十几秒里窗口会显示「正在用该账号的登录态打开
  Dola…」，不再是空白窗口。

★ 黑窗口里一直刷下面这行，一般不用管：
     WARNING:  Invalid HTTP request received.
  这是 uvicorn 在说「收到了一段不是标准 HTTP 的字节」，
  开 VPN / 代理软件时它们会扫描本机端口，属于噪音，不影响使用。

不想要这个功能：启动前设置环境变量 DOLA_WEB_PROXY=0 即可关掉。
想改默认落地页：DOLA_WEB_START=/（默认 /chat/）。
想换成备用域名：DOLA_WEB_BASE=https://你的地址。

七、想做成免安装的 .exe / .app（可选）
----------------------------------------------------------------
说明：dist\DolaPool\ 不是仓库里自带的东西，而是【运行打包命令后现场生成】的
      输出目录（已被 .gitignore 排除，所以仓库里永远看不到它）。
      不打包也完全能用 —— 直接双击 start-windows.bat 就够了，
      只是那种方式要求电脑上装了 Python。

想拿到"别人电脑上不装 Python 也能跑"的程序，两种做法：

【方式一】在自己电脑上打包（需要装一次 Python + PyInstaller）
    pip install -r requirements-desktop.txt pyinstaller
    python tools/build_desktop.py
  执行完成后，打包脚本会打印产物路径，形如：
    Windows  仓库目录\dist\DolaPool\DolaPool.exe
    macOS    仓库目录/dist/DolaPool.app
    Linux    仓库目录/dist/DolaPool/DolaPool
  把整个 DolaPool 文件夹拷给别人，双击即可运行。
  注意 PyInstaller 不能跨平台：Windows 的 exe 必须在 Windows 上打。

【方式二】用 GitHub 云端打包（本机什么都不用装）
    1. 把仓库推到 GitHub（仓库里已带 .github/workflows/build-desktop.yml）
    2. 打开仓库 → Actions → 选 "Build Desktop App" → Run workflow
    3. 跑完后在该次运行页面底部 Artifacts 里下载 DolaPool-Windows，
       解压就是我们给你打好的 DolaPool\DolaPool.exe
    打 tag（如 v2.0.11）推送时还会自动建 Release，三平台产物都挂上去。


八、出问题了怎么办
----------------------------------------------------------------

【v2.0.12 的事故，v2.0.13 已修】双击 DolaPool.exe，弹一个红叉窗口：
   "Unhandled exception in script / Failed to execute script 'desktop'
    ... AttributeError: 'NoneType' object has no attribute 'isatty'
    ... ValueError: Unable to configure formatter 'default'"

   原因：exe 是「窗口程序」（PyInstaller --windowed），这种程序**没有控制台**，
   于是 sys.stdout / sys.stderr 是 None；而 uvicorn 的默认日志配置会去拿
   sys.stderr 再调 isatty() 判断要不要上色 → 直接抛异常 → 程序还没起来就退出。
   （用 start-windows.bat 启动时因为有控制台，反而看不到这个问题。）

   v2.0.13 起：
    · 没有控制台时自动换成「写日志文件」的替身流（有 isatty，返回 False）；
    · 不再用 uvicorn 自带的 dictConfig，日志由启动器自己配（文件 + 有控制台时也打屏）；
    · 万一还有别的启动异常，会写一份 crash-时间.log 并弹一个**中文**提示框，
      不会再甩这串英文堆栈。
   日志和崩溃记录都在：
    Windows  %APPDATA%\DolaPool\desktop.log（崩溃是 crash-*.log）
    macOS    ~/Library/Application Support/DolaPool/desktop.log
    Linux    ~/.local/share/dola-pool/desktop.log

【最常见】双击 start-windows.bat 后，黑窗口一闪就没了 / 完全没反应
   <重要> 请务必先【解压】压缩包，再到解压出来的文件夹里双击。
          直接在压缩包预览窗口里双击，程序找不到自己的文件，必然出错。

   然后按顺序试：

   1) 在文件夹空白处按住 Shift + 右键 → "在此处打开 PowerShell 窗口"
      （或地址栏输入 cmd 回车），手动敲这两行看具体报错：

          python --version
          start-windows.bat

      窗口会停住不关闭，把报错内容截图即可。

   2) 如果 python --version 报错或弹出应用商店：
      说明没装 Python。到 https://www.python.org/downloads/ 下载安装，
      安装第一屏【务必勾选】 "Add Python to PATH"（或"Add python.exe to PATH"）。

   3) 如果提示"已被系统阻止 / 已保护你的电脑"：
      Windows 给下载来的文件加了标记。右键 start-windows.bat →
      属性 → 底部勾选"解除锁定" → 确定，再双击。
      或点"更多信息" → "仍要运行"。

   4) 如果之前运行到一半失败过，可能留下坏的 .venv 文件夹：
      删掉文件夹里的 .venv 目录再试（新版启动器已能自动重建）。

   5) 手动完整流程（最可靠，任何情况都能用）：

          cd /d 你的解压目录\DolaPool
          python -m venv .venv
          .venv\Scripts\python.exe -m pip install -r requirements-desktop.txt
          .venv\Scripts\python.exe desktop.py

      界面出不来时，最后一行换成：
          .venv\Scripts\python.exe desktop.py --browser
      会用系统默认浏览器打开界面，同样能用。


【最常见 2】装依赖时报错：Failed to build 'pyyaml' / Could not find Cython
   （报错里会有一堆 pypi.org 连接超时、SSL EOF）

   原因有两层：
     · 你的网络连 Python 官方源 pypi.org 不稳定；
     · 旧版依赖里的 pyyaml 需要"现场编译"，编译又要再从 pypi 抓 Cython，
       网络一断就彻底失败。

   新版已经解决：
     · 依赖里去掉了会拉 pyyaml 的 uvicorn[standard]（附带的包用不上）；
     · 三个平台的启动器都会【自动依次尝试】：官方源 → 清华镜像 → 阿里云镜像。

   如果你用的是旧压缩包，或想立刻手动解决，直接执行（复制整行）：

     .venv\Scripts\python.exe -m pip install -r requirements-desktop.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

   想永久换镜像（一劳永逸，以后 pip 都快）：

     .venv\Scripts\python.exe -m pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

   如果报错里出现 "free-threaded" 字样，说明你装的是自由线程版 Python，
   很多包还没有对应的预编译文件 —— 请改装普通版 Python 3.12。


【最常见 3】应用启动即崩溃，报错里出现：
   System.ArgumentException: 参数"picture"必须是可用作 Icon 的图片
   （或 未经处理的异常 … System.Drawing.Icon.Initialize）

   原因：Windows 下窗口图标必须是 .ico 格式，旧版误用了 .png，
        .NET 直接抛异常导致进程崩溃。

   新版已解决：Windows 自动使用 .ico、其他系统用 .png，
   并且在传图标前会先校验文件有效性，读不了就干脆不带图标启动。

   另外那次崩溃时你可能会看到 "[1/4] Python found:" 后面是空的 ——
   那是启动器的另一个 bug（虚拟环境已存在时忘了给变量赋值），也已修好。
   现在这里会正常显示 Python 版本号。


【最常见 4】验活/检查账号时报错，提示里出现：
   联网检查失败：Invalid header value b'[\n {\n'
   （或 Invalid header value、http.client.InvalidURL 之类）

   原因：账号的 Cookie 字段里存的其实是**一段 JSON 文本**，
        不是 Cookie 本身。常见于直接把导出的 .json 文件、
        浏览器插件导出的 {"name":..,"value":..} 数组当 Cookie 粘了进来。
        验活时这段 JSON 被当成 HTTP 请求头发出去，Python 就直接报错。
        （这跟有没有开 VPN 无关。）

   新版已解决：
   1) 粘贴 JSON 时会自动从里面把 Cookie 抽出来再保存，
      验活时如果发现是历史遗留的坏数据，也会自动提取并修好，
      并在提示里告诉你「已从粘贴内容中自动提取 Cookie」。
   2) 识别不了内容时会直接拒绝并说明原因，不会再抛那句天书报错。

   如果看到下面这句，说明粘贴的内容里确实没有 Cookie：
     识别出这是 JSON，但里面没有可用的 Cookie 字段
   —— 请按上面第「二」节第 3 步重新复制 Cookie 文本。


【v2.0.16 更新：撤回「2.5 优先」，改成浏览器扩展路线】

★ 为什么撤回
  上一版把 Seedance 2.5 + 30 秒放到了最前面，但**它并没有实际作用**：
  生成核心直接用接口提交 2.5 时，多数账号会被服务端按「只支持 4~15 秒」拒掉。
  所以这版把默认改回真正能用的 2.0 Fast。

★ 生成页现在的默认
  · 模型：Dreamina Seedance 2.0 Fast（默认，5 / 10 / 15 秒，默认 10 秒）
  · 2.5 仍然留在下拉里，但标注「多数账号调不到，别当默认」，
    选中时会用黄色字提醒。要试可以试，失败不会怪到程序头上。
  · 上一版的「网页右下角 ⚡ 生成助手」小条已删除（它只能在网页菜单里点，
    站点没开放 2.5 时同样点不出来）。

★ 新的 2.5 / 30 秒路线：浏览器扩展（🧩）
  30 秒和 2.5 是**网页端靠扩展解锁**的，而这个扩展必须跑在真正的
  Edge / Chrome 里 —— WebView2 内核（软件里的账号窗口）装不了扩展。
  所以这版改成：把扩展放进程序目录，然后用带扩展的浏览器打开 Dola。

  1) 把扩展解压到程序目录的 extensions 下，保证某一层目录里有 manifest.json：
       DolaPool\extensions\dola30\manifest.json
     （如果是 Extensions.zip，直接解压到 extensions\ 即可，多套一层也能识别）
  2) 打开软件 → 左侧【账号池】→ 顶部「🧩 浏览器扩展」卡片
     会列出：识别到的扩展名、本机找到的 Edge / Chrome 路径。
  3) 点【🧩 带扩展浏览器打开】→ 会用独立 profile 启动 Edge/Chrome 并打开
     https://www.dola.com/chat/ 。首次需要在这个窗口里登录一次，之后会记住。
  4) 在网页里正常生成即可；扩展自己会把 30 秒选项加进时长菜单。

  说明与边界：
  · 软件只是「把扩展装进浏览器的启动参数」：
      msedge.exe --user-data-dir=<数据目录>\extension-browser
                 --disable-extensions-except=...\extensions\dola30
                 --load-extension=...\extensions\dola30 https://www.dola.com/chat/
  · 这个窗口和软件里的账号窗口互不影响，登录态各自保存。
  · 能不能真的出 30 秒，最终由 Dola 服务端决定；扩展只是让网页「敢请求」30 秒。
    被服务端拒的话，网页会自己提示「只支持 4~15 秒」，那不是本软件的问题。
  · 没找到扩展 / 没找到 Edge 或 Chrome 时，卡片会直接写原因，按钮是灰的。

【v2.0.15 更新：画布教程/演示、体检 404 误报】

★ 画布：使用说明 + 30 秒演示
  · 顶栏新增【❔ 使用说明】：三种连线方式、工具栏每个按钮干什么、颜色含义、
    快捷键，全写在一页里。
  · 点【▶ 播放演示】：画布会自己一步步搭出「文本输入 + 图片输入 → AI 推理 →
    视频生成」，边搭边提示，最后自动缩放到全图。演示只搭流程，不提交生成、

  · 空画布时顶部会出现一条欢迎提示，可直接点【▶ 看演示】或【❔ 使用说明】。

★ 模型体检：提交端点 404 不再一口咬定「接口改版」
  · GET 一个只接受 POST 的地址，网关常常回 404。现在遇到 404 会再补两次探测：
    OPTIONS（看 Allow 头）和去掉查询串的同路径 GET。

    - 两次都探测不到 → 标成「未知」并提示：先在网页里手动生成一次，
      能出片就说明没改版；
  · 没勾【真实提交一次】时，那一步现在显示「没做」（灰色），
    不会再有红叉，也不会把结论写成「有问题的是：真实提交」。

★ 生成页闪烁
  根因：每 4 秒的刷新会把「最近成片」的 <video> 和「最近任务」整张表重建，
  浏览器于是重新加载视频、重新排版表格 → 看着一直在闪（没有任务时不重建，
  所以不闪，和你观察到的完全一致）。现在 video 元素常驻、只在地址真变时换
  src 并保留播放进度；任务行按 id 增量更新，内容没变就不碰 DOM。

★ 模型体检（生成页 →【🩺 模型体检】）
  用来回答「seedance_v2.5 到底还能不能用」，不消耗额度：
    ① 生成核心：能否导入、提交 URL 能否算出来（纯本地）
    ② 网络：DNS / TCP / TLS 分段计时，哪一步断了一目了然
    ③ 登录态：带着账号 Cookie 打开 dola.com/chat/，被踢到登录页就是 Cookie 失效
    ④ 提交端点：只请求提交地址看路由（404=接口改版；401/403=Cookie 失效；
       400/405/415/422/429=端点还在；5xx=风控或维护）
  勾选【真实提交一次】会真的提交一个 10 秒任务（消耗一次额度、账号里多一条
  会话），回报 conversation_id —— 这是唯一能 100% 确认模型可用的办法。
  注意：体检的「联网」三步依赖你这台机器的网络/代理；如果 ② 就失败，
  说明是网络层（该走代理却直连 / 代理没起来），跟模型本身无关。
