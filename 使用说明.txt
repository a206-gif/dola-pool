================================================================
  Dola Pool 桌面版 · 快速开始
================================================================

一、怎么打开
----------------------------------------------------------------
Windows ：双击  start-windows.bat
macOS   ：双击  start-macos.command
          （若提示"无法打开，因为来自身份不明的开发者"，
            右键 → 打开 → 再点"打开"即可）
Linux   ：终端执行  ./start-linux.sh

首次启动会自动创建运行环境并安装依赖，大约 1-3 分钟；
之后每次启动只需几秒。

前提：电脑上要有 Python 3.10 或更高版本
      下载：https://www.python.org/downloads/
      Windows 安装时务必勾选 "Add Python to PATH"

程序默认是【演示模式】：不联网、不需要账号，任务会在 6 秒左右
生成一段内置示例视频，用来先把整个流程跑通、熟悉界面。


二、要生成真实视频（生产模式）
----------------------------------------------------------------
1. 打开界面 → 左侧【设置】→ 找到「桌面应用」卡片
2. 点【切换到生产模式】→ 窗口会自动重启（几秒钟）
3. 左侧【账号池】→【批量导入】→ 粘贴你的 Dola 账号 Cookie
   （每行一个，或拖入 .txt / .csv / .json 文件）

   Cookie 从哪来：浏览器 F12 → Network（网络）→ 随便点一个 dola.com
   的请求 → Request Headers 里的 "Cookie:" 后面那一整行
   （形如 sessionid=xxxxx; sid_guard=yyyyy; ... 是一段带分号的文本，
    不是 JSON）。
4. 左侧【生成】→ 填提示词 → 【提交任务】

注意：生产模式会真实调用 Dola 生成，需要账号自身有可用额度；
      生成逻辑与原始仓库完全一致（含代理轮换与去水印），
      我没有做任何改动。账号与风控风险请自行判断。


三、生成好的视频在哪里
----------------------------------------------------------------
· 界面【任务队列】里点【▶ 播放】可以直接看，弹窗里有
  【📂 打开所在文件夹】和【⬇ 下载】
· 文件保存在（各平台不同）：
    Windows  %APPDATA%\DolaPool\output
    macOS    ~/Library/Application Support/DolaPool/output
    Linux    ~/.local/share/dola-pool/output
· 界面【设置 → 桌面应用】里也有【📂 成片目录】按钮，一键定位


四、常用参数（可选）
----------------------------------------------------------------
命令行运行时可加参数：
    --no-demo        直接以生产模式启动
    --demo           强制演示模式
    --browser        不开原生窗口，用系统默认浏览器打开
    --port 8123      指定端口（默认自动选空闲端口）

例： start-windows.bat --no-demo


五、想做成免安装的 .exe / .app（可选）
----------------------------------------------------------------
说明：dist\DolaPool\ 不是仓库里自带的东西，而是【运行打包命令后现场生成】的
      输出目录（已被 .gitignore 排除，所以仓库里永远看不到它）。
      不打包也完全能用 —— 直接双击 start-windows.bat 就够了，
      只是那种方式要求电脑上装了 Python。

想拿到"别人电脑上不装 Python 也能跑"的程序，两种做法：

【方式一】在自己电脑上打包（需要装一次 Python + PyInstaller）
    pip install -r requirements-desktop.txt pyinstaller
    python tools/build_desktop.py
  执行完成后，打包脚本会打印产物路径，形如：
    Windows  仓库目录\dist\DolaPool\DolaPool.exe
    macOS    仓库目录/dist/DolaPool.app
    Linux    仓库目录/dist/DolaPool/DolaPool
  把整个 DolaPool 文件夹拷给别人，双击即可运行。
  注意 PyInstaller 不能跨平台：Windows 的 exe 必须在 Windows 上打。

【方式二】用 GitHub 云端打包（本机什么都不用装）
    1. 把仓库推到 GitHub（仓库里已带 .github/workflows/build-desktop.yml）
    2. 打开仓库 → Actions → 选 "Build Desktop App" → Run workflow
    3. 跑完后在该次运行页面底部 Artifacts 里下载 DolaPool-Windows，
       解压就是我们给你打好的 DolaPool\DolaPool.exe
    打 tag（如 v2.0.0）推送时还会自动建 Release，三平台产物都挂上去。


六、出问题了怎么办
----------------------------------------------------------------

【最常见】双击 start-windows.bat 后，黑窗口一闪就没了 / 完全没反应
   <重要> 请务必先【解压】压缩包，再到解压出来的文件夹里双击。
          直接在压缩包预览窗口里双击，程序找不到自己的文件，必然出错。

   然后按顺序试：

   1) 在文件夹空白处按住 Shift + 右键 → "在此处打开 PowerShell 窗口"
      （或地址栏输入 cmd 回车），手动敲这两行看具体报错：

          python --version
          start-windows.bat

      窗口会停住不关闭，把报错内容截图即可。

   2) 如果 python --version 报错或弹出应用商店：
      说明没装 Python。到 https://www.python.org/downloads/ 下载安装，
      安装第一屏【务必勾选】 "Add Python to PATH"（或"Add python.exe to PATH"）。

   3) 如果提示"已被系统阻止 / 已保护你的电脑"：
      Windows 给下载来的文件加了标记。右键 start-windows.bat →
      属性 → 底部勾选"解除锁定" → 确定，再双击。
      或点"更多信息" → "仍要运行"。

   4) 如果之前运行到一半失败过，可能留下坏的 .venv 文件夹：
      删掉文件夹里的 .venv 目录再试（新版启动器已能自动重建）。

   5) 手动完整流程（最可靠，任何情况都能用）：

          cd /d 你的解压目录\DolaPool
          python -m venv .venv
          .venv\Scripts\python.exe -m pip install -r requirements-desktop.txt
          .venv\Scripts\python.exe desktop.py

      界面出不来时，最后一行换成：
          .venv\Scripts\python.exe desktop.py --browser
      会用系统默认浏览器打开界面，同样能用。


【最常见 2】装依赖时报错：Failed to build 'pyyaml' / Could not find Cython
   （报错里会有一堆 pypi.org 连接超时、SSL EOF）

   原因有两层：
     · 你的网络连 Python 官方源 pypi.org 不稳定；
     · 旧版依赖里的 pyyaml 需要"现场编译"，编译又要再从 pypi 抓 Cython，
       网络一断就彻底失败。

   新版已经解决：
     · 依赖里去掉了会拉 pyyaml 的 uvicorn[standard]（附带的包用不上）；
     · 三个平台的启动器都会【自动依次尝试】：官方源 → 清华镜像 → 阿里云镜像。

   如果你用的是旧压缩包，或想立刻手动解决，直接执行（复制整行）：

     .venv\Scripts\python.exe -m pip install -r requirements-desktop.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

   想永久换镜像（一劳永逸，以后 pip 都快）：

     .venv\Scripts\python.exe -m pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

   如果报错里出现 "free-threaded" 字样，说明你装的是自由线程版 Python，
   很多包还没有对应的预编译文件 —— 请改装普通版 Python 3.12。


【最常见 3】应用启动即崩溃，报错里出现：
   System.ArgumentException: 参数"picture"必须是可用作 Icon 的图片
   （或 未经处理的异常 … System.Drawing.Icon.Initialize）

   原因：Windows 下窗口图标必须是 .ico 格式，旧版误用了 .png，
        .NET 直接抛异常导致进程崩溃。

   新版已解决：Windows 自动使用 .ico、其他系统用 .png，
   并且在传图标前会先校验文件有效性，读不了就干脆不带图标启动。

   另外那次崩溃时你可能会看到 "[1/4] Python found:" 后面是空的 ——
   那是启动器的另一个 bug（虚拟环境已存在时忘了给变量赋值），也已修好。
   现在这里会正常显示 Python 版本号。


【最常见 4】验活/检查账号时报错，提示里出现：
   联网检查失败：Invalid header value b'[\n {\n'
   （或 Invalid header value、http.client.InvalidURL 之类）

   原因：账号的 Cookie 字段里存的其实是**一段 JSON 文本**，
        不是 Cookie 本身。常见于直接把导出的 .json 文件、
        浏览器插件导出的 {"name":..,"value":..} 数组当 Cookie 粘了进来。
        验活时这段 JSON 被当成 HTTP 请求头发出去，Python 就直接报错。
        （这跟有没有开 VPN 无关。）

   新版已解决：
   1) 粘贴 JSON 时会自动从里面把 Cookie 抽出来再保存，
      验活时如果发现是历史遗留的坏数据，也会自动提取并修好，
      并在提示里告诉你「已从粘贴内容中自动提取 Cookie」。
   2) 识别不了内容时会直接拒绝并说明原因，不会再抛那句天书报错。

   如果看到下面这句，说明粘贴的内容里确实没有 Cookie：
     识别出这是 JSON，但里面没有可用的 Cookie 字段
   —— 请按上面第「二」节第 3 步重新复制 Cookie 文本。


【其它】
· start-windows.bat 里的提示是英文的 → 因为中文写在批处理里会导致乱码
  甚至窗口闪退（编码问题），所以批处理里只用英文；中文说明就是本文件。
· 提示 GTK/QT 加载失败    → Linux 缺 GUI 库，用 --browser 参数先跑起来
                           或 sudo apt install python3-gi gir1.2-webkit2-4.1
· 任务一直是"失败"        → 检查【账号池】里有没有导入可用 Cookie
· 导入后账号一直"检查中"  → 联网验活依赖 Dola 官方接口，接口没配置时
                            只做本地格式检查，不影响提交任务
